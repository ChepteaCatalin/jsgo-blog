# How am I learning React?

<PostImage src={Cover} title="How am I learning React?" />

28 October 2026

I’m already comfortable using React, but I want to understand what happens under the hood.

I’ve read plenty of documentation and articles, watched videos, and tried other learning resources, but I feel like they only scratch the surface. Eventually, I realized that the best way for me to understand React in depth is to dig into its source code. That’s why I set it up locally.

## Setting up the React source code locally

I cloned the repository from GitHub and installed the necessary dependencies.

The surprising part is that they still use Yarn v1.

I found [this issue](https://github.com/react/react/issues/31334), which is still open, by the way. So, I had to find a workaround for this TypeScript declaration problem. I applied the changes from [this PR](https://github.com/react/react/pull/35856) to my local React version, and I got the same error again.

After a session with Claude, it told me to run `yarn --cwd compiler install --frozen-lockfile`, which is the same step CI uses in `.github/workflows/runtime_build_and_test.yml`. **Basically, even though React doesn’t provide meaningful documentation on how to build it locally, you can just read its GitHub workflows and follow the same steps**.

It worked, but it took me **1587.84s (~26.5 minutes)**. Surprisingly long for a local build.

The `build` folder contains 1352 items and ~116.4MB.

Next, I created a React app using Vite. However, I needed a way to link my app to the local React source code so I could experiment with it. For now, I decided to use Vite aliases:

```ts
// vite.config.ts

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { resolve } from "node:path";
import { fileURLToPath } from "node:url";

const here = fileURLToPath(new URL(".", import.meta.url));
const localPackages = resolve(here, "../react/build/oss-stable");

const local = (name: string) => resolve(localPackages, name);

export default defineConfig({
  plugins: [react()],

  resolve: {
    alias: [
      {
        find: /^react$/,
        replacement: local("react"),
      },
      {
        find: /^react\/jsx-runtime$/,
        replacement: local("react/jsx-runtime"),
      },
      {
        find: /^react\/jsx-dev-runtime$/,
        replacement: local("react/jsx-dev-runtime"),
      },
      {
        find: /^react-dom$/,
        replacement: local("react-dom"),
      },
      {
        find: /^react-dom\/client$/,
        replacement: local("react-dom/client"),
      },
      {
        find: /^scheduler$/,
        replacement: local("scheduler"),
      },
    ],
    dedupe: ["react", "react-dom", "scheduler"],
  },
  optimizeDeps: {
    include: [
      "react",
      "react-dom/client",
      "react/jsx-runtime",
      "react/jsx-dev-runtime",
      "scheduler",
    ],
  },

  server: {
    sourcemapIgnoreList: () => false,
  },
});
```

Then, I opened my browser dev tools and navigated to the `Sources` tab to verify that the local React source code was being used. I could see the files from the `react/build/oss-stable` directory, confirming that the Vite aliases were correctly pointing to the local React source code.

Then, I clicked on `Remove from ignore list` to ensure that the local React source code would not be ignored by the dev tools.

Now, I can debug and experiment with the local React source code directly in my browser dev tools, making it easier to understand how React works internally.

Hopefully, I won't get bored with this in a couple of days. Even if I do, any amount of digging into React would be beneficial. At least it's better than watching TikTok all day long.
